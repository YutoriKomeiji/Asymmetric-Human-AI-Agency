# Safety-LCA Implementation Checklist

This checklist verifies whether a system truly enforces Safety-LCA
at the architecture level.

If any item fails, the system is **not Safety-LCA compliant**.

---

## 1. Agency & Authority

- [ ] Humans are the only entities allowed to make irreversible decisions
- [ ] AI outputs are never executed automatically
- [ ] AI cannot commit, deploy, send, publish, or mutate records
- [ ] All irreversible actions require explicit human confirmation
- [ ] No default acceptance exists

---

## 2. Responsibility Pathways

- [ ] Every irreversible action has a defined pathway
- [ ] Pathway includes:
  - AI Output
  - Human Interpretation
  - Explicit Decision
  - Human Confirmation
  - Irreversible Action
- [ ] No steps are merged or skipped
- [ ] No automation crosses the confirmation boundary
- [ ] Broken pathways are detected and blocked

---

## 3. Explicit Responsibility Points (ERPs)

- [ ] Decision owner is always a specific human
- [ ] Decision time is recorded
- [ ] Decision context is recorded
- [ ] Responsibility cannot be inherited or transferred implicitly
- [ ] If no owner exists, the action cannot execute

---

## 4. Irreversibility Control

- [ ] Irreversible actions are clearly defined
- [ ] Irreversible actions are separated from preparation steps
- [ ] AI can prepare but cannot cross the boundary
- [ ] Human confirmation is mandatory for each irreversible action
- [ ] Batch or chained irreversible actions are blocked

---

## 5. Autonomy Management

- [ ] Maximum autonomy level is explicitly defined
- [ ] Autonomy increases require design-level changes
- [ ] Temporary automation has an expiration
- [ ] Autonomy drift is detected and logged
- [ ] Drift is treated as a bug, not a feature

---

## 6. Visibility & Awareness

- [ ] Decision moments are visible to humans
- [ ] Decision points feel interruptive (not silent)
- [ ] No pre-checked boxes or silent defaults
- [ ] Humans are aware when responsibility is taken
- [ ] System never hides responsibility transitions

---

## 7. Logging & Accountability

- [ ] Decision logs are immutable
- [ ] Logs bind action to human identity
- [ ] Logs bind action to time and context
- [ ] Logs are reviewable
- [ ] Logs cannot be generated by AI alone

---

## 8. Failure Detection

- [ ] Missing decision owner triggers a failure
- [ ] Skipped confirmation triggers a failure
- [ ] Merged pathway triggers a failure
- [ ] Silent execution triggers a failure
- [ ] System fails closed, not open

---

## Final Rule

> If you cannot answer **who decided**, **when**, and **with what context**,  
> the system must not act.

This is not a UX checklist.
This is a **safety gate for system design**.
